## Value

you can see at a glance how open work flows: what has to land before what, where
chains are long, and which single item holds back the most. Today the status page
lists blocked items one card at a time, so the shape of the dependencies isn't visible.

## Scope

in: a map section on the HTML page from `npm run status -- --html`, drawn from P11's
graph JSON — blockers on the left and the work they hold back to the right, with an
arrow for each dependency; colour and shape that show each item's kind (feature, bug,
assumption, decision) and its state (ready, in flight, blocked, waiting on you); drawn
by the script itself, so the page still loads nothing from the internet. out: a map in
the text report; interaction beyond what plain HTML gives (title-text tooltips are
fine); shipped and closed items, except a closed item that still blocks something
(such as an abandoned dependency).

## Accept

- I can see every open item on the map, with arrows running left to right from what blocks to what it blocks.
- Without reading any text, I can tell which items are ready, in flight, blocked or waiting on me.
- A chain such as P2 → P1 → A-1 reads as one row of three boxes in dependency order.
- The page still opens with no network connection.

## Notes

Triaged 2026-10-20 from the owner's request on accepting P7. On the day it was drafted,
main had almost no dependencies between open items, so the map would show mostly
unconnected boxes until real chains exist.

Plan: yes — a new drawn section on the status page, with its own layout.
