## Value

/implement's step-1 gates (claim, depends, milestone, spike, premise) are run by hand
from prose at the start of every build, and a misread gate fails silently. Most of
them have one right answer from the docs and git, so code should give it.

## Scope

- R0 (report-only): `scripts/preflight.mjs <ID>` reads the trunk through
  trunkGraph and reports the claim, depends (transitive), milestone and spike gates,
  plus a premise table: each path or symbol named in Scope or Accept, searched with
  grep-checked, marked found / VERIFIED absent / NOT evidence. A "found" row never
  clears a premise; the session still checks each claim. /implement runs it beside its
  manual gates, and the close report says whether they agreed.
- R1 (after the agreement gate, program Phase 3): preflight becomes the gate, and the
  prose for those gates in /implement shrinks to a pointer.
- Out: judging whether a behavioral claim holds.

## Accept

- On a claimed entry, an entry resting on an open A-n or D-n, or one whose P#
  dependency is unshipped, preflight names the failed gate and the blocker and exits
  non-zero; on a ready entry it exits 0.
- A Scope naming a file that no longer exists shows that row as VERIFIED absent; a
  search that couldn't run shows as NOT evidence, never as absent.
- In R0, every close report states whether preflight matched the manual gates, so the
  agreement gate can be counted from git.
- (R1) /implement refuses to start when preflight exits non-zero, without re-running
  the gates by hand.
