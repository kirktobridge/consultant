## Value

When the owner hands back an abandoned claim, the loop has no way to resume it: the
claim gate says stop, so the session resumes outside the rules. Preflight's correct
"claim FAIL" then reads as a disagreement in the count that decides whether preflight
becomes the gate, and once it is the gate a resumed build could not start at all.

## Scope

- In: `preflight.mjs <ID> --resume` treats an `in-progress` claim as this build's when
  the entry's own `feat/` branch exists, and reports it as resumed, naming the branch.
  It still refuses when the branch has a recent commit or holds the land lock, since
  that claim may be live.
- In: /implement's claim gate names this path for a claim the owner hands back, and
  says what a resume does first: commit any uncommitted work in the worktree, rebase
  onto the trunk, then run the gates.
- Out: deciding whose claim it is without the owner's word. `--resume` is the owner's
  permission, trusted, not checked.

## Accept

- With the entry `in-progress`, its own branch present and no recent commit on it,
  `preflight.mjs <ID> --resume` reports the claim as resumed, names the branch, and
  exits 0 if the other gates pass.
- Without `--resume`, with no branch for the entry, or with a recent commit on its
  branch, the claim fails as it does now.
- /implement's claim gate tells a resumed build to commit leftover work and rebase
  before running the gates.
