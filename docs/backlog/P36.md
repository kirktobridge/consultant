## Value

the claim gate and next.mjs can't disagree about what an entry on the trunk says.
Today each has its own copy of the reader, and they already differ in how they
treat an entry they can't read.

## Scope

- One function in entries.mjs reads a register off a ref (list the dir, filter by
  idPattern, show each file untrimmed, parse); claims.mjs and next.mjs both call it.
- A file it can't read, or whose header doesn't parse, is an error the caller
  reports. It is never read as an empty or unclaimed entry.
- Out: the other scripts' readers of the working tree (loadRegister).

## Accept

- An entry on the trunk whose first line isn't `---` makes both `node scripts/next.mjs`
  and `node scripts/claims.mjs` exit 2, naming the file.
- On a trunk with ordinary entries, both still give the answers they give today
  (the existing next and claim-gate tests pass unchanged).
