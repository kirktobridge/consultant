## Value

The session audit and `npm run status` read the trunk through trunkGraph, and the
program's preflight and groom tools will too. Today an entry whose header won't parse
vanishes from that graph and the run still succeeds: the audit shows only a generic
"N violation(s)" line, and status shows nothing. A claimed or blocking entry can
disappear from every view that reads it.

## Scope

- trunkGraph compares the register files on the trunk with the entries in the graph.
  A file that matches a register's ID pattern but is missing from the graph makes it
  return `failed`, naming the file. Its callers already stop or report on `failed`.
- New readers of the trunk (P41's preflight, P42's groom) read through trunkGraph,
  not their own copy.
- Out: claims.mjs, next.mjs and worktree.mjs keep their own readers. A malformed entry
  reaches the trunk only when the hooks are bypassed (pre-commit runs the schema check;
  /land re-runs the suite on the merge). If one of them misreads such an entry, that's
  a bug report.

## Accept

- An entry on the trunk whose first line isn't `---` makes `npm run status` exit 2 and
  the session audit print "Ahead: unreadable", both naming the file.
- On a trunk with ordinary entries, both give the answers they give today (the
  existing tests pass unchanged).
