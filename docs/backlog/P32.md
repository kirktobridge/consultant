## Value

A blocked entry can't get a worktree, even if its claim reached main anyway (hooks
not installed, `--no-verify`, or a dependency that reopened after the claim). Today
only the commit-time schema check and /implement's prose hold that line.

## Scope

- `worktree.mjs start` reads the entry's `depends_on:` from main and refuses (exit 1)
  when any is unmet: a `P#` not `shipped`, a `B#` not `fixed`, an `A-n` or `D-n`
  still `open`. The message names each one and its status.
- Applies to new worktrees and to resuming an existing one.
- The "is this dependency met?" rule moves into `scripts/entries.mjs`, and both
  `next.mjs` and `worktree.mjs` use it, so they can't disagree.
- Out: transitive chains (the schema check already walks those at claim time), and
  any per-milestone exception (P30 removes that).

## Accept

- On a claimed entry that depends on an open assumption or decision, `node
  scripts/worktree.mjs start <ID>` exits 1, creates no branch or worktree, and names
  the dependency and its status.
- The same refusal happens for a claimed bug, and for an entry whose worktree
  already exists.
- Once the dependency is settled, the same command creates (or resumes) the worktree.
