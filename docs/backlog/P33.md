## Value

Small changes that are not worth an entry (a prose rewrite, a doc fix) still need a
worktree, the lock, the rebase and the suite on the merged result. Today
worktree.mjs and /land both refuse them, and the only way through is a hand-made
worktree and a direct merge without the lock. That merge can collide with a
landing that another session is running, and nothing records that the change
happened outside the loop.

## Scope

An ad-hoc lane, marked by the branch prefix `adhoc/`:
- `worktree.mjs start --adhoc <slug>` cuts `adhoc/<slug>` off local main into its own
  worktree, with no claim gate.
- /land and land.mjs take the branch through the lock, the rebase, the merge with the
  full suite, and finish. They skip what only an entry supplies: the close report,
  the acceptance hand-off and /ship's flips.
- The merge commit carries an `Ad-hoc: <what>` trailer, and an optional
  `Relates: <ID>…` trailer that links it to existing entries.

Out: deciding which work is too big to be ad-hoc; the staleness use of `Relates:` (P34).

## Accept

- `worktree.mjs start --adhoc <slug>` creates `adhoc/<slug>` and its worktree off
  local main, with no backlog or bug ID.
- An `adhoc/` branch lands through /land: lock, rebase, merge, full suite, worktree
  removed. Main is put back if the suite is red. No close report is asked for and
  no /ship flips run.
- The ad-hoc merge commit carries an `Ad-hoc:` trailer. land.mjs refuses the merge
  when that trailer is missing, or when a `Relates:` ID does not exist in any register.
- A `feat/p#-…` or `feat/b#-…` branch with no close report is still refused, exactly
  as today.

Landed 2026-10-20 (merge d29e272): `worktree.mjs start --adhoc` and land.mjs's
`--adhoc`/`--relates` trailers; /land's skill has an ad-hoc section. No milestones.
