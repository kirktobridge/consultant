## Value

The graph is meant to be the one contract for what blocks what, but it leaves out a
dependency on an ID with no entry. Its own text view then lists that entry under
"Start now", and trunk-graph.mjs has to re-parse every header to recover what the
graph dropped (B9's fix), so two parsers of depends_on can drift.

## Scope

- The schema check's graph() emits each `depends_on:` on an ID with no entry,
  beside its edges, and `--graph` (text) lists such an entry as blocked, naming the
  ID, not under "Start now".
- trunk-graph.mjs reads that field instead of re-parsing headers; its missingDeps
  goes. status and the session audit read the same as they do after B9.
- GUIDE.md's graph section and tests/graph.test.mjs carry the new field. It is
  additive, so GRAPH_VERSION stays 1 unless a consumer breaks.

## Accept

- On a trunk where an entry's `depends_on:` names an ID with no entry, `--graph`
  lists that entry as blocked, naming the ID, and not under "Start now".
- On B9's repro, status and the session audit give the same output as before this
  change, and trunk-graph.mjs no longer reads register headers to find the missing ID.
- tests/graph.test.mjs holds the new field's shape, and GUIDE.md's graph section
  documents it.
