## Value

The scripts stop disagreeing about what git said. Today each carries its own copy of
the git call, and the copies differ: some trim output (which quietly repairs an entry
header with a leading BOM or blank line, and eats the first column of
`git status --porcelain`), most keep only stderr when git fails (so a hook that reports
on stdout leaves an empty reason), and buffer sizes vary.

## Scope

- In: every script under `scripts/` that runs git itself moves to `gitIn` from
  `scripts/git.mjs`, which ship.mjs, worktree.mjs and land.mjs already use (ad-hoc
  merge 8545bec).
- In: `gitIn` grows the options the remaining callers need (stdin input and a larger
  buffer for trunk-graph.mjs; a quiet mode for the schema check, which discards git's
  stderr today), rather than those scripts keeping private copies.
- In: a test that fails when a script other than git.mjs calls git directly.
- Out: changing what any script reports, except where moving it changes trimming or
  error text; each such change is named in the commit and tested.

## Accept

- A test fails when any script in `scripts/` other than git.mjs calls git directly, and it names the script.
- An entry on main whose header starts with a BOM is reported as unreadable by every script that reads entries from main, not read as valid.
- When git fails inside a script, the script's message gives git's own reason even if git printed it only on stdout.
- The existing test suite passes; any test changed to fit a new message is named in the commit.
