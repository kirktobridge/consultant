## Value

the backlog stops saying `shipped` about something no user can reach.
Today `shipped` means the user accepted it; the event that follows — it's live — has
no representation at all.

## Scope

- R0: status vocab gains `released` downstream of `shipped` (accepted), with both meanings
  stated here; checker and /ship's flip table updated in the same commit.
- R1: a `/release` skill holding the project's real deploy procedure as a PORTING
  slot (the idiom is /verify's launch recipe), plus the version recorded on the entry.
  /release refuses an entry that isn't `shipped`.
- Out: rollback automation, CI wiring, changelog generation.

## Accept

- An entry that is accepted but not deployed reads `shipped`, and no entry reads
  `released` until it is actually reachable.
- `/release` flips it to `released` and records which version went out.
- A project with no deploy step passes the doc check with nothing ever `released`,
  and is never nagged about it.

## Notes

must degrade gracefully for projects with no deploy step — `released` stays
an optional terminal state, never one the audit nags for, or the check loses
credibility in exactly the projects that ported it fastest.

acceptance handshake (6043955) made merged-but-unaccepted stay `in-progress` and
`shipped` mean accepted. So the lifecycle is in-progress → shipped (accepted) →
released (deployed). R0 claimed 2026-10-16.
