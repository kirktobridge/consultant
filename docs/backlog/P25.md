## Value

The session audit is the first thing the user reads each session, and right now it
gives one instruction for every non-refuted outcome: "these are now unblocked …
consider promoting one into the queue". For a `moved` assumption that's wrong. Nothing
was settled, the entry was refiled, and an open dependent still points at a dead ID
that the schema check will fail. If the user follows the advice, a broken entry goes
into the queue.

## Scope

- In: section 4 of `scripts/session-audit.mjs` picks its advice by status. `moved`
  names `moved_to:` and says to re-point each open dependent's `depends_on` there via
  /ship, not to promote it. `moot` says the question stopped mattering, so dependents
  should be re-read for scope before they're promoted. `verified` and decisions keep
  the "unblocked" advice. `refuted` doesn't change.
- In: dependents that are already terminal aren't something to promote. If a
  `verified` assumption or a decision has only terminal dependents, the audit doesn't
  report it. A `refuted` one still lists shipped dependents, because shipped work may
  rest on the false premise.
- In: a test per status that pins the advice.
- Out: changing the schema check, which already fails open entries that depend on a
  moved ID.

## Accept

- When an assumption flips to `moved` with an open dependent, the audit names the
  `moved_to` target and tells the user to re-point. The words "unblocked" and
  "promote" don't appear.
- A `moot` assumption with a dependent gets advice that's different from the
  `verified` case.
- The output for `verified`, decided, and `refuted` is unchanged, so the existing
  tests pass without edits.
- An assumption verified today whose only dependent is `shipped` produces no finding.
  The same setup with a `refuted` assumption still raises the alert and names the
  shipped entry.
