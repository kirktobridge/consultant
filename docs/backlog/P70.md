## Value

Parallel builds today are subagents sharing one checkout: nothing stops one from
writing into another's worktree, the main checkout, or main's ref, and a hook can't
see where a Bash command writes. Run as a separate process started in its own
worktree with the sandbox on, a build cannot write outside that worktree, and the
OS enforces it, not a rule the build has to follow.

## Scope

- R0: `scripts/build-process.mjs <ID>` launches a claimed entry's build as
  `claude -p` started in the entry's worktree, with generated sandbox settings: the
  sandbox on, and writes denied to main's ref, `packed-refs`, `.git/config`, `HEAD`,
  `index`, `hooks`, and every other worktree's `.git/worktrees/<name>/`. /implement,
  run this way, stops after its rebased, reviewed commit and hands back; it never
  claims or merges, since both write main.
- R1: /orchestrate claims and cuts each worktree itself from the main checkout,
  dispatches one build process per entry, relays each question by resuming that
  process with the owner's answer, and runs /land from the main checkout for each
  build that hands back ready, one at a time under the land lock.
- Out: interactive sessions; a single /implement run by the owner in their own
  session (unchanged).

## Accept

- A build process that tries to write into the main checkout, another worktree, main's ref, or `.git/config` fails with "Read-only file system", and its own commit on its branch still succeeds.
- `/orchestrate 2` builds two entries as separate processes, and each lands through /land from the main checkout.
- A build that stops with a question continues with the owner's answer and lands.

## Notes

Probed 2026-10-29 with headless `claude -p` (Linux binary, the one at
CLAUDE_CODE_EXECPATH; the `claude` on PATH here is the Windows one and can't use WSL
paths). Harness `isolation: "worktree"` did not stop a Bash write into the main checkout.
`sandbox.enabled` makes everything outside the start folder read-only except `.git`;
`sandbox.filesystem.denyWrite` on the paths above held against git config, update-ref,
raw writes, rm and touch (checksums unchanged), while the build's own commit and the
land lock worked. One run per probe. A-13 settled the resume: it keeps context and
sandbox when the same settings are passed again. Shares the claim-and-cut step with
P66, and the unlocked rebase with P67.

Plan: yes — it changes /orchestrate's dispatch, /implement's close, and adds a
launcher; milestones.
