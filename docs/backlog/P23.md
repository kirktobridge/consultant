## Value

the queue claims every entry in it is dependency-ready, and a claim means
someone is building on its dependencies right now. Today both checks read only
`A-n` dependencies, so an entry waiting on an unshipped `P#` can be queued
ahead of it, or claimed before it exists.

## Scope

- Build the `depends_on` graph once, from the shared entry reader, and have the
  queue and claim gates both read it.
- Queue: an entry may sit below an unshipped `P#` it depends on, directly or
  through another entry, as long as every unshipped one sits above it in the
  queue. Working the queue in order then keeps it dependency-ready.
- Claim: an `in-progress` or `partial` entry fails if any `P#` it depends on,
  directly or through another entry, is not `shipped`.
- Out: transitive `A-n` gating, and making `partial` count as met (see Notes).

## Accept

- Queuing an entry whose dependency is an unshipped `P#` not queued above it fails,
  and the message names both IDs; queued directly below that dependency, it passes.
- Flipping an entry to `in-progress` while any `P#` it depends on, directly or
  through another entry, isn't shipped fails the check, naming the unmet one.
- A dependency that is `deferred` or `abandoned` fails at both the queue and the
  claim.
- A dependency cycle fails the check, naming the cycle.
