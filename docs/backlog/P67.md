## Value

A build takes the land lock and only then rebases, so conflict resolution, the
one-sided-region stop (which waits for the owner) and the re-run suite all happen
while every other session waits on that lock. Rebasing first, without the lock, moves
that work out of it; the locked rebase then usually has nothing left to do.

## Scope

- In: an unlocked rebase in the branch's worktree (`land.mjs rebase --early`), with
  the same conflict recording and the same `continue`, `--why` and `--owner` flow, and
  its resolutions kept for `land.mjs report`.
- In: /implement's close runs it before `lock take`; the locked rebase stays.
- In: P52's resume step ("rebase onto the trunk") is the same command. Build it once,
  here or in P52, whichever is built first.
- Out: dropping the locked rebase.

## Accept

- With main moved since the branch was cut, `land.mjs rebase --early` puts the branch on main without the lock, and the locked `land.mjs rebase` after it reports no conflicts.
- A conflict the early rebase meets stops with exit 3 as a locked one does, and a one-sided resolution stops for the owner the same way, with no lock held.
- Conflicts resolved early show in `land.mjs report` for /land, as locked ones do.
