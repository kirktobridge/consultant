## Value

an exported copy's skills and docs never send a reader to an entry that
isn't there, or to a seed that happens to share the ID. Today /implement cites
A-11 and A-12 and the backlog README names P24, so in a clean copy those lines point
nowhere, or at the wrong D-1.

## Scope

- A check, run in `npm test`, that fails when a suite file agents read as
  instructions (skills, GUIDE, register READMEs, README, PORTING, template/) cites a
  `P#`, `A-n` or `D-n` that is one of this repo's instance entries. It reads the
  suite/instance split from `scripts/manifest.mjs`.
- Rewrite each citation it finds so the sentence stands on its own: keep the rule,
  drop the pointer, or move the provenance into the entry that bought it.
- Out: test fixture IDs (they name the fixture's own entries), and provenance tags
  in code comments ("(P15)"); the product owner kept those out for now (2026-10-19).

## Accept

- Adding "see P24" to a skill fails `npm test`, and the message names the file, the
  line and the ID.
- Seed IDs in template/ (P1, A-1, D-1) and fixture IDs in tests/ don't trip it.
- After the rewrite, the suite passes and no skill, GUIDE, README or PORTING line
  cites an instance ID.

## Notes

Found while building P28 (2026-10-19). About 35 citations sit in instruction prose,
and about 300 more are fixture IDs and comment tags, deliberately out of scope.

Plan: yes — a new check plus rewritten citations across the suite's prose.
