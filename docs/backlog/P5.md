## Value

you report "this is broken" and it lands with repro and severity intact,
instead of being dressed as a feature with an invented `Value:` line. Urgent breakage
can jump the queue without corrupting what the queue means.

## Scope

- R0: a `B#` register of its own, `docs/bugs/` (own README; added to the registers
  `scripts/entries.mjs` reads). Header: `id`, `title`, `status` (`open` /
  `in-progress` / `fixed` / `wontfix`), `severity` (`critical` / `major` / `minor`),
  `reported` (date), `depends_on`. Body: `## Repro` required while open; `## Value`
  not required; `## Expected` / `## Notes` optional. /triage's classification test
  gains a fourth class — feature / assumption / decision / **it's broken**. Schema
  check learns the shape.
- R1: queue semantics — severity above a bar bypasses [QUEUE.md](QUEUE.md) ordering
  rather than being ranked into it; /implement accepts a `B#`, and its DEPENDS GATE
  still applies.
- Out: anything resembling a bug tracker — no external sync, no duplicate detection.

## Accept

- Reporting "this is broken" produces a `B#` entry keeping my repro steps and a
  severity, with no invented `Value:` line.
- A `B#` above the severity bar gets picked up next without being ranked into
  `## Next up`.
- /implement accepts a `B#` id, and still refuses one blocked by an open D-n or A-n.
