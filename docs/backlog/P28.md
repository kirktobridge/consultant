## Value

the suite can be dropped into another project at any time, and you know
it works there. Today this repo is the suite and the project that builds it at once,
with nothing recording which files are which. Every entry built here risks tying
the suite a little more to this repo's own backlog and state.

## Scope

- A manifest, in code, that marks every tracked file as *suite* (skills, scripts,
  hooks, tests, eval, register READMEs, PORTING) or *instance* (this repo's entries,
  queue, LESSONS entries, SPEC, ARCHITECTURE, drills). A check fails when a tracked
  file isn't marked.
- `scripts/export.mjs <dir>` writes the suite files, plus each register in a minimal
  valid starting state (a seed entry where the schema check requires one), and
  CLAUDE.md with its PORTING placeholders.
- A `test:clean` npm script exports to a temp dir and runs `npm install` + `npm test`
  there. CI runs it; the pre-commit hook does not, because it doubles the suite's
  time.
- Fix what the clean run exposes: tests that pass only because this repo's own
  entries exist. Each one either moves onto a fixture or is marked instance-only.
- Out: deciding when to release, which the product owner handles; versioning or
  publishing.

## Accept

- The `test:clean` script passes on a fresh export, run on a machine with only Node
  installed.
- Adding a tracked file without marking it suite or instance fails the check,
  naming the file.
- The exported copy contains none of this repo's entries, assumptions, decisions or
  drill files, and its own schema check passes.
- A test that reads this repo's own entries fails the clean run until it is moved
  onto a fixture or marked instance-only.
