## Value

A plan: yes entry gets the plan I asked for even when a session skims /implement.
Today the PLAN GATE is prose, so a session that misses it builds without asking, and
nothing notices until the close report.

## Scope

- `worktree.mjs start <ID>` reads the entry's `plan:`. On `plan: yes`, without
  `--plan-approved`, it refuses (exit 1) and names the plan gate. Resuming an existing
  branch needs no flag: that branch was cut after approval. Bugs, `plan: no` entries
  and `--adhoc` starts are unchanged.
- /implement's PLAN GATE moves ahead of `worktree.mjs start`: the plan is written from
  the main checkout, and start is run with the flag only after the owner approves.
  /orchestrate's prompt changes to match (a subagent asks its plan QUESTION before
  start, and the claim lock is not held across the wait).
- Out: proving the approval happened. The flag catches a session that forgot the gate,
  not one that passes it without asking.

## Accept

- `worktree.mjs start` on a `plan: yes` entry without `--plan-approved` exits 1, names
  the plan gate, and creates no branch; with the flag it creates the worktree.
- A `plan: no` entry, a bug, an ad-hoc start, and a resume of an existing branch all
  start without the flag.
- /implement's eval cases still score at their baseline after the reorder, including
  the plan-gate cases.
