## Value

Dropping an entry, or handing a claim back, is a hand edit to tracked docs today: the
status line, a dated note, MANUAL-ORDER.md, a regenerated QUEUE.md. That is the kind of
multi-file change ship.mjs exists to make in one locked commit, and a missed file
(an abandoned ID left in the recorded order) only shows up later.

## Scope

- In: `ship.mjs abandon <P#> --owner "<their words>"` and `ship.mjs defer <P#> --owner
  "<their words>"`. In one commit under the land lock: set the status, append a dated
  Notes line with the owner's words, remove the ID from MANUAL-ORDER.md, regenerate
  QUEUE.md. Works on a `proposed` or `in-progress` entry.
- In: `ship.mjs unclaim <P#|B#> --owner "<their words>"`: `in-progress` back to
  `proposed` (a bug: `open`), same transaction.
- In: each refuses while the entry's branch exists, naming it. Removing the worktree
  and branch stays a separate step, so no work gets thrown away inside a docs commit.
  Each also refuses while an open entry depends on the one being abandoned or
  deferred, naming those entries.
- In: /ship's prose names these commands where it now describes the hand edit.
- Out: removing worktrees or branches; bugs' `wontfix`.

## Accept

- `ship.mjs abandon P# --owner "…"` makes one commit on main that sets `abandoned`, adds the owner's words with the date, takes the ID out of MANUAL-ORDER.md and regenerates QUEUE.md; `defer` does the same with `deferred`.
- `ship.mjs unclaim P# --owner "…"` turns an `in-progress` entry back to `proposed` in one commit.
- Each refuses with exit 1 and says why while the entry's branch still exists, or while an open entry depends on it (naming them).
- /ship's prose points to these commands, not to a hand edit.
