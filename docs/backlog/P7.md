## Value

you can ask "where are we?" and get an answer without reading markdown —
what landed, what's in flight and since when, what's blocked and on what. Today the
history lives in git (`npm run history`) and the audit runs at session start; both
are addressed to the next session, not to you.

## Scope

a read-only `/status` that composes what already exists (backlog statuses,
assumption and decision blocks, `npm run audit`, git) into a short report addressed to the product owner
rather than to the next session. Out: any new tracked file — if it needs storage,
it's the wrong design. Renders from P11's graph JSON, both as the text report and as
one self-contained HTML page, generated and never edited by hand, stamped with the
commit it was built from.

## Accept

- I can open one page that shows what's ready, what's waiting on me, and why each
  blocked item is blocked, without opening a markdown file.
- It names what is in flight (each entry with its branch and worktree) and how long
  it has been there.
- It names what is blocked and which assumption is blocking it.
- Running it leaves every tracked file unchanged.

## Notes

P4 changed what this entry reads (*verified* against the /land, /implement
and /ship text, 2026-10-15). Acceptance state now exists, in three places:
per-criterion verdicts in the feature commit's message; "waiting on me" = an entry
still `in-progress` whose merge is on main (/land never flips `shipped`); and the
acceptance itself in the entry's `Shipped:` line. All three are free prose, not
fields. So "what's waiting on me" is now concrete, but rendering *which criteria*
passed means parsing commit messages unless P11's graph carries them — a design
question for whoever builds this, not settled here.

P11's graph JSON (shipped 2026-10-16) carries no criteria: an
entry is `id, register, status, open, title` (*mechanically enforced*: the contract test
in tests/graph.test.mjs holds the shape GUIDE.md documents). Its edge `field` values are each repo's own header names
(`depends_on` here, `Depends on` in photocull), so a renderer serving both treats
`field` as a label, never matches on it.

Landed 2026-10-20 (merge 7586dee): `npm run status` (text, `--html` to the gitignored
`.claude/status.html`, `--json`). Ships as an npm script, not `/status`, which is
Claude Code's built-in command; whether a slash command is wanted, and its name, is
the owner's call. No milestones; P7 stays `in-progress` until the user accepts it.

## Shipped

2026-10-20, on the user's word after seeing the per-criterion report and screenshots of
the page. All four criteria observed, two of them with gaps the user accepted knowingly:
the blocked view (criteria 1 and 3) was seen only on a throwaway repo, since main had
nothing blocked; the in-flight duration was seen live only for a same-day claim. The
user is content with `npm run status` and no slash command.
