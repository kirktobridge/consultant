## Repro

1. Same f.py and worktrees as B14's Repro.
2. In p2: set line 3 to "    go()", commit. Land it: lock take, rebase, merge, finish.
3. In p1: set only line 3 to "            go()", commit. lock take, then `node scripts/land.mjs rebase`.
4. It exits 0: "rebased onto main …, no conflicts". `git log` on feat/p1-one shows only main's history: p1's commit is gone.

## Expected

The branch's commit is not dropped without a word: `land.mjs rebase` either replays it (conflicting here) or stops and names the commit it would drop.

## Notes

git rebase skips a commit whose patch-id matches one upstream, and patch-id ignores whitespace. `git rebase --reapply-cherry-picks` (or a check of the branch's commit count before and after) may be the fix. Found 2026-10-28 while reproducing B14.
