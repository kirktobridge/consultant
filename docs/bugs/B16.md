## Repro

1. Put on main a queue of P1 (in-progress), P2 (`depends_on: P1`) and P3.
2. Run `node scripts/next.mjs`: it proposes P3 and prints `skipped: P2 — waits on P1 (in-progress)` (P37).
3. Run `node scripts/session-audit.mjs`: its "Ahead" block says `next up: P2`, waiting on P1.

## Expected

The banner's "next up" is the entry `node scripts/next.mjs` proposes, for the same reason, in every queue state.

## Notes

session-audit.mjs already runs `next.mjs --json` for a ready bug, but works out the queue head itself as "the first queued entry nobody has claimed". It should take next.mjs's queue pick (`next` with `from: 'queue'`, and `skipped`) from that same call. Found by /code-review on P37, 2026-10-28. Fold in the cosmetic gap the owner agreed to: next.mjs words one landed claim as "awaiting acceptance" in a single pick and "awaiting the owner's acceptance" in a batch.
