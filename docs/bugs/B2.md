## Repro

1. /land merged B1: `node scripts/land.mjs merge feat/b1-session-audit-reports-clean`.
2. It printed `merged … into main (3213ae1); suite green.` with no test count.
3. /land ran `npm test` itself to get one; through the rtk hook the `ℹ tests / pass /
   fail` lines are filtered out, so its report said it had no fresh count from main.

## Expected

`land.mjs merge` prints the suite's totals on a green merge, and says so plainly when
the suite's output has none. /land reports the count from there, without running the
suite a second time.

## Notes

`land.mjs merge` already captures the suite's output (it reads it on the red path),
and discards it on the green one. The rtk filtering is installation config, not this
repo's; reading the count from land.mjs takes the loop off it.

Fixed 2026-10-20 on the user's word (merge eab208c): Repro no longer reproduces and the first Expected line observed, both by /verify B2 before landing. The second Expected line ("/land reports the count from there, without running the suite a second time") was accepted knowingly half-observed: no second run happened, but the landing ran main's pre-merge land.mjs, so it had no count to report. The next /land is the first that can show it.
