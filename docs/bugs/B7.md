## Repro

The gaps B6 was accepted with, in scripts/landing.mjs (read by status.mjs and
next.mjs):

1. A squash is found by the entry's ID in its commits, and nothing enforces that a
   branch's commits carry it. A squash that names the ID nowhere reads as being built.
2. The owner rejects a landing, and the landed branch is reused for the rebuild. Until
   its first new commit, the entry reads as landed, awaiting acceptance.
3. With no build branch in this clone, a commit made straight on main that names the
   ID (`docs: … (P15)`, touching a skill) reads as the entry landing.

## Expected

(1) A commit on an entry's branch that doesn't name the ID is refused, and the suite
fails on one already merged. (2) Once the rejection is recorded, the entry reads as
being built. (3) A tagged commit made directly on main is not a landing, and a build
branch that exists only on a remote counts as one.
