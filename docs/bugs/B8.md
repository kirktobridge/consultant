## Repro

1. In a clone of this repo, set P30's header to `depends_on: P99` (no P99 entry
   exists) and commit it on main with `--no-verify`, so the schema check doesn't stop it.
2. `node scripts/status.mjs` exits 0, prints nothing on stderr, and lists P30 under
   "Ready to start (18)".
3. `node scripts/session-audit.mjs` on the same clone prints "(backlog-schema: the
   check has 1 violation(s); the graph may be wrong until they're fixed (npm run
   check:docs))" under Ahead. status.mjs takes only `{ graph, failed }` from
   trunkGraph and never reads its `warning`.

## Expected

The status report says the graph may be wrong, as the session audit does, in every
form it renders (text, `--json`, `--html`), so a ready list drawn from a graph that
dropped an edge doesn't read as a sound one.

case, it needs a malformed entry on main with the hooks bypassed.

Fixed 2026-10-23 on the owner's word (merge e2590af): the Repro no longer breaks and
