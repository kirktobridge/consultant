## Repro

1. In this repo, whose only trunk is `main`: `node scripts/session-audit.mjs --base mian`
2. It printed `session-audit: clean (base mian) — statuses match reality, tree committed.` and exited 0.

## Expected

An unknown `--base` stops the script with exit 2 and says how to name the trunk, as
`node scripts/next.mjs --base mian` already does. The same holds for every script that
takes `--base`.

## Notes

Found by P12's code review, then observed. The scripts validate `--base` each their
own way; `scripts/trunk.mjs` has `resolveTrunk(branches, base)`, which validates and
words the fix once, and claims.mjs and trunk.mjs already use it. Routing every script
through it fixes this. A bare `--base` with no value is the same class: next.mjs
silently falls back to auto-detection. review.mjs takes any commit as its base on
purpose, so only its branch-name case belongs here.

Fixed 2026-10-20 on the user's word: Repro no longer reproduces and both Expected lines accepted as observed by /verify B1 (merge 3213ae1).
