## Options

(a) No: `shipped` stays the owner's word per entry, as today. A continuous run waits
whenever nothing ready is left but acceptances are pending.
(b) Opt-in per run: the owner starts a run with auto-accept, and it flips `shipped`
only for a clean landing (every Accept criterion *observed*, suite green, no question
asked during the build). Anything else stops for the owner. Each flip records the
opt-in as its `--owner` words; the run ends with a list of what it auto-shipped, and
`ship.mjs reject` is the undo.
(c) As (b), but `plan: yes` entries never auto-accept.

## Context

Raised 2026-10-30 (owner: "we could make it a mode where auto-accept applies"). A
dependent waits for its dependency to be `shipped`, so a continuous run over a chain
(P52 → P54 → P66) stalls on each acceptance. D-7 already hands a bug's `fixed` to the
agent when its report clears it; a feature's `shipped` stayed the owner's because its
Accept needs their judgment. The cost of auto-accept is a late rejection: entries built
on a rejected one may need rework. A continuous orchestrate run rests on this.
