## Options

(a) A recorded owner order: ready entries the owner has ordered go first, in that
order; the rest are ranked by what they unblock. P24's generator reads it. (b) Real
dependencies only: the unblock-count ranking decides everything not forced by
`depends_on:`. (c) The owner re-asserts an order by hand on each refresh; nothing
records it.

## Context

The backlog README says the owner can overrule any ranking, but nothing records an
overrule: every /ship refresh re-ranks by the rule, and P24 as drafted fails the check
on any hand ordering. The first order to need recording is the codification
program's (approved 2026-10-21): Phase 0 prepare → Phase 1 read-only tools (P21 first)
→ Phase 2 `ship.mjs` → Phase 3 enforce and regroup → Phase 4 collapse → Phase 5
parked. Its soft preferences ("read-only before writers") are not dependencies and
would be lost under (b).

## Decided

(a): a recorded owner order goes first; the computed ranking orders the rest.

The recorded order, as filed so far: P21, P40, P36, P22, P41, P25, P42, P43, P44, P45,
P46, P47, P48, P49, P24, P39, P37. Program items
not yet filed are inserted at their place as /ship files them. Since P24 landed
(2026-10-24), the record is [docs/backlog/MANUAL-ORDER.md](../backlog/MANUAL-ORDER.md),
which the queue generator reads; this list is history.

## Why

The product owner's choice, 2026-10-21. An overrule that the next refresh erases was
never an overrule.

## Reopen if

The recorded order goes stale faster than it's maintained — entries in it sit unready
while the computed ranking would have moved work.
