title: In a worktree session, which git commands does the isolation guard allow?
status: verified

## Assumption

inside a session isolated in a worktree by EnterWorktree, Claude Code
runs a plain, single git command aimed at the session's own worktree, and runs
`node <script>` whose script calls git itself. It refuses a compound command that
names git: a pipe, a `&&` chain, a heredoc or `node -e` whose text mentions git, or
a path containing `.git`.

## Why it matters

P15 R2 issues every lock, rebase, check and merge step either as
one plain git command or as a node script. If the guard starts refusing either, R2's
landing stops partway, and the session is left inside a half-finished rebase.
The harness belongs to Claude Code and can change with any update.

## How to verify

in a worktree session entered with EnterWorktree `path`, run each of
the following and record what is allowed and what is refused:

- a plain `git rebase <ref>` that conflicts, then `--abort`;
- the same rebase, resolved with Edit, then `git add` and
  `git -c core.editor=true rebase --continue`;
- `node <script>` whose script creates a file in the git common dir;
- `git status && git log`, which should be refused.

The P15 end-to-end /verify drill covers all of these. Re-run it after a Claude Code
update. A git-rewriting plugin such as rtk is a per-installation case and its
workaround lives in that installation's config; it is out of scope here.

## Resolution

Verified 2026-10-19 during P15 R1's build and the full rebase probe that
followed (*observed*; see P15's Notes and R1's commit message).

- **Allowed:**
  - a plain `git rebase` that stops at the conflict with exit 1 and names it;
  - `git diff --name-only --diff-filter=U`;
  - `git rebase --abort`, which restores the branch tip;
  - Edit + `git add` + `git -c core.editor=true rebase --continue`;
  - plain commits;
  - a node script file that creates a lock in the git common dir exclusively (a
    second exclusive create got EEXIST).
- **Refused:**
  - a `&&` chain naming git;
  - a heredoc whose text mentions git;
  - `node -e` with git inline;
  - a shell write to a path containing `.git`.

  Each refusal said the guard "cannot verify that it stays inside the worktree".
- **Not tested:** whether a node script can run git against *another* checkout from
  inside the session. R2 must not depend on it either way. Its merge runs only after
  ExitWorktree, from the main checkout.
