---
id: A-13
title: Can a sandboxed headless build stop for the owner and be resumed with their answer?
status: open
raised: 2026-10-29
---

## Assumption

A build run as `claude -p` inside its worktree, with the sandbox on, can end its turn
on a question, and `claude -p --resume <session-id>` started from the same worktree
with the same settings continues it with its earlier context, under the same sandbox.

## Why it matters

Process-per-build orchestration (drafted 2026-10-29, not yet filed) relays the owner's
answers this way: a separate process can't be resumed with SendMessage, as a subagent
is today. If resuming loses the context or the sandbox, a build that stops for the
owner has to start over, or continue unfenced.

## How to verify

In a throwaway worktree, start a sandboxed `claude -p --output-format json` whose
prompt has it remember a random word and end by asking a question. Take its
`session_id`, then resume it with an answer from the same worktree and settings. It
holds if the resumed run names the word, and a write it tries into the main checkout
still fails with "Read-only file system".
