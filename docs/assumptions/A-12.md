## Assumption

a subagent can do what a top-level session does in P15: start its
worktree from the main checkout, enter it with EnterWorktree `path`, and leave it
with ExitWorktree `keep` to land from the main checkout.

## Resolution

Refuted 2026-10-19 by probe (*observed*). A plain (non-isolated)
subagent at the repo root calling EnterWorktree `path` on an existing worktree under
`.claude/worktrees/` was refused: "switching is only available to sessions whose
working directory is inside a worktree of this repository". The same subagent's
ExitWorktree was refused: "cannot be called from a subagent with a cwd override …
it would mutate the parent session's process-wide working directory". A
worktree-isolated subagent is pinned inside a harness-made worktree. It can't run
`worktree.mjs start` (that refuses a linked worktree) and can't exit to land.

Broke: P17's dispatch as scoped, "worktree-isolated subagent per entry … P15's
machinery handles the claim and the worktree". P15's flow runs only in top-level
sessions. A-9 still holds: a subagent can run the forked skills, but not this
flow's worktree moves.
